[ 02 — THE MECHANISM ]

A boundary.
Not a promise.

Trust isn't another checkbox in an admin panel. The authorization boundary must remain meaningful when the agent — or the application — makes a mistake.

01

Propose freely.

Agents negotiate and prepare structured transactions. They never hold the execution key.

02

Authorize independently.

Cryptographic policy checks the exact action and required approvals.

03

Verify before execution.

An independent executor verifies the authorized payload. No valid proof, no action.

[ 03 — FAILURE BY DESIGN ]

The agent can be wrong.
The gate can say no.

Even a convincing prompt injection should not become a valid authorization. The transaction boundary is where a proposal becomes — or fails to become — an action.
